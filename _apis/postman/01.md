# Postman documentation overview
<br>
Postman Docs에 오신 걸 환영합니다!
이 문서는 API 프로젝트에서 Postman을 활용하는 방법을 안내하는 공식 문서입니다.

Postman에서 실행할 수 있는 작업 및 워크플로는 아래 주제에서 확인하세요:

## Get started
Postman을 처음 사용한다면 [Get started]({% link _apis/postman/02.md %}) 섹션을 확인하세요.

## Send requests
Postman에서는 작업 중인 API에 요청을 보낼 수 있습니다. 요청을 보내는 자세한 방법은 [Postman에서 API 요청 보내기와 응답 데이터 받기]({% link _apis/postman/03.md %}) 문서를 참고하여 [첫 번째 요청]({% link _apis/postman/docs/02/01_first/send_a_request.md %})을 보내보세요.

## Write scripts
Postman은 [Node.js](https://nodejs.org/ko) 기반 런타임을 제공해 요청과 컬렉션에 동적 동작을 추가할 수 있습니다. 요청 전후에 스크립트를 실행하여 API 테스트를 수행할 수 있고, 동적 파라미터를 포함한 요청을 구성하며, 요청 간 데이터를 전달할 수 있습니다. 자세한 내용은 [스크립트를 사용하여 Postman 요청에 로직과 테스트 추가하기]({% link _apis/postman/04.md %}#use-scripts-to-add-logic-and-tests-to-postman-requests)를 참조하세요.

## Use collections
Postman Collection은 저장된 요청들을 묶은 그룹입니다. 컬렉션을 사용하면 요청을 체계적으로 관리하고 그룹화할 수 있으며, 다수 요청을 함께 실행할 수 있습니다. 컬렉션은 수동으로, 예약 실행으로, CI/CD 파이프라인 또는 웹훅(webhook)를 통해 실행할 수 있습니다. 자세한 내용은 [Postman 컬렉션으로 API 요청을 구성하고 자동화하기]({% link _apis/postman/05.md %})를 참고하세요.

## Use Postman Flows
Postman Flows는 API 워크플로를 시각적으로 구성할 수 있는 도구입니다. Flows를 활용해 요청을 연결하고, 데이터를 처리하며, Postman 워크스페이스 내에 실제 서비스에 가까운 워크플로우를 만들 수 있습니다.

자세한 내용은 [Postman flows를 이용하여 API를 시각적으로 구성하기]({% link _apis/postman/09.md %})를 참고하세요.

## Use the Postman CLI
Postman CLI는 Postman용 보안이 강화된 명령줄 도구입니다. Postman CLI를 사용하여 컬렉션을 실행하고, 실행 결과를 postman으로 전송하며, API 명세를 API 거버넌스(API Governance) 및 보안 규칙에 맞춰 검사할 수 있습니다.

자세한 내용은 [Postman의 명령줄 도구 살펴보기]({% link _apis/postman/05.md %}#explore-postmans-command-line-companion)를 참고하세요.

## Collaborate in Postman
Postman은 팀 내 [협업](https://www.postman.com/api-platform/api-collaboration/)을 지원하고 강화할 수 있는 다양한 도구를 제공합니다. 내부 워크 스페이스를 생성해 팀원들과 작업을 공유하고, API 프로젝트에서 함께 협업할 수 있습니다. 또한 사용자는 Postman 내에서 컬렉션과 API뿐 아니라, 개별 요청, 버전, API 정의 및 스크립트의 특정 위치(인라인)에도 댓글을 남기고 작업에 대해 토론할 수 있습니다.

자세한 내용은 [Postman에서 협력하기]({% link _apis/postman/06.md %}#collaborate-in-postman) 문서를 참고하세요.

## Design and develop your API
Postman은 Spec Hub, 컬렉션의 Types, API Builder로 [API-First](https://www.postman.com/api-first/) 개발을 지원합니다.[Spec Hub]({% link _apis/postman/07.md %}#design-apis-with-specifications) 와 [API Builder]({% link _apis/postman/07.md %}#develop-apis-with-the-api-builder)를 사용해 각각 API 사양(specification) 또는 정의(definition) 형태로 API 구조를 설계할 수 있습니다.또한 [컬렉션의 Types]({% link _apis/postman/07.md %}#design-apis-with-collections)을 활용해 Postman Collection 포맷으로 API를 설계할 수도 있습니다.

API-first 개발 방식에 대한 자세한 내용은 [Design and build your APIs in Postman]({% link _apis/postman/07.md %}#design-and-build-your-apis-in-postman) 문서를 참고하세요.

## Document your API
[문서화](https://www.postman.com/api-platform/api-documentation/)는 모든 컬렉션과 API에서 중요한 요소입니다. 잘 작성된 문서는 컬렉션을 사용하는 사람이 해당 컬렉션의 기능과 각 요청의 동작 원리를 이해하는 데 도움이 됩니다. 또한 좋은 API 문서는 사용자가 어떤 엔드포인트를 사용할 수 있는지, 그리고 그 엔드포인트와 어떻게 상호작용해야 하는지를 명확히 알려줍니다.

컬렉션이나 API의 문서를 생성하시면, 사용자는 Postman 내에서 해당 문서를 확인할 수 있습니다. 기본값은 비공개이므로, 다른 사람이 접근하려면 해당 컬렉션이나 API를 공유해야 합니다. 만약 공개 API를 만들고 계시다면, 문서를 게시(publish) 하여 웹 브라우저를 사용하는 누구나 열람할 수 있도록 공개할 수 있습니다.

자세한 내용은 [Document your APIs in Postman]({% link _apis/postman/06.md %}#document-apis) 문서를 참고하세요.

## Monitor your API
Postman Monitor를 사용하면 API의 상태와 성능을 지속적으로 점검할 수 있습니다. [모니터](https://www.postman.com/api-platform/api-monitoring/)를 이용하면 API 테스트 스크립트를 실행하고, 여러 개의 요청을 순차적으로 연결하며, 중요한 API 플로우를 검증할 수 있습니다. 모니터는 사용자가 설정한 일정에 따라 Postman 클라우드에서 일련의 요청들을 실행합니다. 모니터에 대한 자세한 내용은 [Postman에서 API 상태와 성능 모니터링하기]({% link _apis/postman/05.md %}#monitor-collections)를 참고하세요.

## API Governance and API Security
[API 거버넌스](https://postman.com/api-platform/api-governance/)는 조직 내 모든 환경의 API가 일관되게 동작하도록 개발 규칙을 정의하고 적용하는 운영 체계를 말합니다. 견고한 [API 보안](https://www.postman.com/api-platform/api-security/) 체계란 조직이 보안 우선 원칙에 따라 API를 설계하고 구현하도록 장려하는 개발 규칙을 갖추고 있음을 의미합니다. Postman의 API Governance와 API Security 기능은 API에서 일관성 문제나 보안 취약점을 식별하고, 적합한 수정·개선안을 제공합니다.

이와 관련된 자세한 내용은 [Postman의 API Governance 및 API Security]({% link _apis/postman/08.md %}#postman-enterprise) 문서를 참고하세요.

## Administration
Postman은 초기 설정부터 지속적인 팀 및 요금제 관리까지, Postman 운영 환경을 맞춤 구성할 수 있는 다양한 옵션을 제공합니다. 팀 관리자(Team Admin)는 팀의 온보딩 절차를 간소화하고, 접근 권한을 관리하며, 팀이 Postman의 최신 버전을 사용할 수 있도록 관리할 수 있습니다.

자세한 내용은 [Team management overview]({% link _apis/postman/08.md %}#team-management)를 참고하세요.

## Use reports
Postman은 팀의 Postman 사용 현황 데이터를 시각화한 보고서를 제공합니다. 이 보고서를 통해 테스트, 문서화, 모니터링 적용 범위 등을 포함한 API 상태를 파악할 수 있습니다. 또한 API 성능과 SLA 준수 여부도 확인할 수 있습니다.

자세한 내용은 [View reports on usage, security, and billing in Postman]({% link _apis/postman/08.md %}#postman-enterprise)을 참고하세요.

## Developer resources
CI/CD 워크플로에 Postman을 연동하거나 Postman API 또는 라이브러리로 개발하는 경우, [Postman developer resources]({% link _apis/postman/13.md %}#postman-developer-resources)를 참고하세요.

## Integrations
범용 서드파티 솔루션과의 연동(integrations)을 통해, Postman을 API 워크플로와 연결할 수 있습니다. 연동을 사용하면 Postman과 API 개발에 사용하는 다른 도구 간에 데이터를 자동으로 공유할 수 있습니다.

자세한 내용은 [Integrate Postman with third-party solutions]({% link _apis/postman/01.md %}#integrations)을 참고하세요.

# Resources about APIs and Postman
<br>
API와 Postman에 대해 더 깊이 배우고 싶다면 Postman이 제공하는 여러 학습 도구들을 활용해 보세요. Postman 앱의 [training collections](#training-collections), [collection templates](#collection-templates), [Quick Help](#quick-help)로 지식을 쌓거나, [API Lifecycle](https://www.postman.com/api-platform/api-lifecycle/)에 대해 배울 수 있습니다. 강사 진행 워크숍, 자율 학습 과정, 인증 과정은 [Postman Academy](#postman-academy)에서 제공합니다. 새로운 기능과 개선 사항은 [release notes](#release-notes) 페이지에 지속적으로 업데이트됩니다.

## Training collections
Postman의 [워크스페이스, 컬렉션 등](https://www.postman.com/explore)을 아래 실습 컬렉션으로 살펴보세요:

- [Learn by API](https://www.postman.com/postman/published-postman-templates/collection/bperikk/learn-by-api) — API 입문 개념부터 시작해 보세요.

- [Postman Training](https://www.postman.com/postman/postman-galaxy-training/overview) — APIs 101, 테스트와 자동화, API 도입, API-First 실습을 통해 API의 핵심 내용들을 배워보세요.

## Postman Academy
[Postman Academy](https://academy.postman.com/)는 모든 수준의 학습자를 위한 종합 학습 포털입니다. 강사 진행 및 자율 학습 코스를 이용할 수 있으며, 퀴즈와 실습 과제로 학습한 내용을 점검할 수 있습니다.

## Locating Postman logs
Postman은 문제가 발생할 경우를 대비해 로그 메시지를 자동으로 기록합니다. 이 로그에는 최근 앱 활동 정보가 포함되어 있으며, 문제를 진단하고 해결할 때 도움이 됩니다.

운영체제별로 로그를 확인하려면, Postman을 열고 각각 다음의 단계를 따르세요:

- macOS: 상단 메뉴에서 **View > Developer > View Logs in Finder**를 클릭합니다.

- Windows: 상단 메뉴에서 **View > Developer > View Logs in Explorer**를 클릭합니다.

- Linux: 상단 메뉴에서 **View > Developer > View Logs in File Manager**를 클릭합니다.

로그 파일을 찾았다면, 해당 파일을 [Postman Support Center](https://www.postman.com/support/) 요청서에 첨부하세요. 이 로그는 지원팀이 문제를 더 정확하게 진단하고 해결하는 데 도움이 됩니다.

## Accessing the Devtools console
DevTools 콘솔은 Postman의 내부 디버깅 로그를 제공하며, 이 정보는 앱에서 문제가 발생했을 때 유용하게 활용할 수 있습니다.

Postman에서 DevTools 콘솔 로그를 확인하려면, 상단 메뉴에서 **View > Developer > Show DevTools (Current View)** 를 클릭합니다. DevTools 창에서 Console 탭을 클릭하면 앱의 디버그 로그를 확인할 수 있습니다.

## Checking Postman's status
Postman에 문제가 발생한 경우, [Postman Status](https://status.postman.com/) 페이지에서 Postman의 성능 저하, 서비스 중단, 또는 유지보수 여부 등의 서비스 상태를 확인할 수 있습니다.

## Hardware acceleration
Postman은 컴퓨터의 내장 그래픽 하드웨어를 활용해 화면 그래픽 렌더링 속도를 높입니다. 컴퓨터에서 사용하는 GPU 모델, 드라이버, 또는 운영체제에 따라 하드웨어 가속이 문제를 일으킬 수도 있습니다. 화면 아티팩트 및 기타 이상 현상이 발생한다면, 하드웨어 가속을 끄는 것이 문제 해결에 도움이 될 수 있습니다.

Postman에서 하드웨어 가속을 활성화 또는 비활성화 하는 방법은 다음과 같습니다:

- **macOS** - 상단 메뉴에서 **Postman > Hardware Acceleration**을 클릭합니다.

- **Windows** 또는 **Linux** - 상단 메뉴에서 **Help > Hardware Acceleration**을 클릭합니다.

새 설정을 적용하려면 Postman을 재시작하세요.

## Connection issues
데이터 가져오기 실패나 오류 메시지 등의 네트워크 연결 문제가 있는 경우, 아래 순서대로 점검해 보세요:

1. 운영체제에서 Postman 앱을 강제 종료합니다.

2. Postman 데스크톱 앱을 다시 실행합니다.

3. 상단 메뉴에서 **Help > Clear Cache and Reload**를 클릭합니다.

문제가 계속되면, Postman 웹 앱에 로그인해 계정을 확인해 보세요. 웹 앱에서도 연결 문제가 있다면 VPN이나 프록시를 끄고, 다른 네트워크에 연결해 보세요.

여전히 Postman 서버에 연결되지 않는다면, Postman 도메인을 허용 목록(allowlist)에 추가하세요. 자세한 방법은 [Use Postman behind a firewall]({% link _apis/postman/docs/02/04_install/installation_and_updates.md %}#use-postman-behind-a-firewall) 문서를 참고하세요.

## Other issues

이 가이드는 Postman 앱의 문제 해결에 초점을 둡니다. 다른 유형의 이슈는 아래 문서를 참고하세요.

- API 요청 관련 문제를 해결하려면 [Troubleshooting requests]를 확인하세요.

- Postman Monitors 관련 문제는 [Troubleshooting monitors]를 확인하세요.

- Agent Mode 관련 문제를 해결하려면 [Agent Mode troubleshooting]를 확인하세요.

- Insights 관련 오류를 해결하려면 [Diagnose and troubleshoot Insights errors]를 확인하세요.

- WebSocket 요청 관련 문제는 [Troubleshoot WebSocket requests]를 확인하세요.

- Postman Vault 관련 문제는 [Troubleshoot vault secrets]를 확인하세요.

- Postman에서 프록시 설정과 관련된 문제는 [Troubleshooting proxy configurations]를 확인하세요.

- 결제 및 청구 관련 문제는 [Troubleshooting billing]을 확인하세요.

- 사용자 지정 도메인으로 호스팅하는 API 문서의 DNS 오류 관련해서는 [Troubleshoot DNS issues]를 확인하세요.
